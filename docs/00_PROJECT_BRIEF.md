# Project Brief v0.1

## 1. 项目目标

开发一个 macOS 桌面端 ECG 分析算法项目，用于读取 BIDMC 示例 CSV 数据，对 ECG 与 PPG 信号从 125Hz 降采样到 50Hz，并在降采样后的 50Hz ECG 信号上检测 R 峰，计算 RR 间期，最终导出逐采样点 CSV 结果。

本项目定位为研究 / 工程分析工具，不作为医疗诊断软件。

## 2. 项目非目标

本阶段不做：

1. 医疗诊断结论输出；
2. HR 输出；
3. HRV 指标输出，例如 RMSSD、SDNN、pNN50；
4. 复杂心律异常分析，例如早搏、房颤、漏搏临床解释；
5. 算法准确性大规模验证。

## 3. 输入数据与字段

已确认：

1. 数据源：BIDMC CSV。
2. 示例文件：`bidmc_01_Signals_2500.csv`。
3. 仓库内路径：`data/examples/bidmc_01_Signals_2500.csv`。
4. 原始采样率：125Hz。
5. 时间戳字段：`Time [s]`，单位秒。
6. ECG 导联字段：原始 CSV 中可能为带前导空格的 ` II`；列名匹配时采用 `strip()` 策略，标准名为 `II`。
7. PPG 字段：原始 CSV 中可能为 `PLETH` 或带前导空格的 ` PLETH`；列名匹配时采用 `strip()` 策略，标准名为 `PLETH`。

## 4. 输出结果与字段

采用逐采样点输出结构。建议导出 CSV 每行对应一个 50Hz 采样点，至少包含：

1. `sample_index_50hz`：50Hz 下的采样点索引；
2. `time_s`：降采样后的时间戳；
3. `ecg_50hz`：降采样后的 ECG；
4. `ppg_50hz`：降采样后的 PPG；
5. `r_peak`：是否为 R 峰，0 / 1；
6. `rr_ms`：当前 R 峰对应 RR 间期，非 R 峰行为空值。

正式导出 CSV 字段使用上述标准字段名。

## 5. ECG 算法范围

已确认：

1. ECG 和 PPG 均从 125Hz 降采样到 50Hz。
2. 时间戳同步降采样。
3. R 峰检测顺序为：先降采样到 50Hz，再检测 R 峰。
4. 需要检测 R 峰。
5. 需要输出 RR。
6. 不需要输出 HR。
7. 不需要输出 HRV。

算法本阶段以工程可用为主，不做临床级性能承诺。

## 6. 桌面端功能范围

需要 CLI + GUI。

CLI 最小功能：

1. 指定输入 CSV；
2. 执行降采样、R 峰检测、RR 计算；
3. 导出逐采样点 CSV；
4. 输出基本运行摘要，例如 R 峰数量、RR 范围、是否有异常 warning。

GUI 最小功能：

1. 选择 CSV；
2. 运行分析；
3. 显示 50Hz ECG 波形；
4. 在波形上标出 R 峰；
5. 显示结果表格；
6. 导出 CSV。

## 7. 技术栈与平台默认假设

已确认：

1. 平台：macOS。
2. 技术栈：Python。
3. 可最大化利用第三方库。
4. 推荐第三方库：`pandas`、`numpy`、`scipy`、`matplotlib`。
5. GUI 库后续里程碑再定，候选为 PySide6 或 Tkinter。

## 8. 测试与验收标准

当前阶段验收方式：

1. 没有 R 峰参考标注；
2. 先采用 smoke test + 可视化 + RR 合理性验证；
3. 接受工程合理性标准；
4. 异常数据只做基础处理。

算法类里程碑至少验证：

1. CSV 可读取；
2. 必要字段存在；
3. 时间戳间隔符合 125Hz 预期；
4. 降采样后采样率为 50Hz；
5. 能完成 R 峰检测；
6. R 峰数量合理；
7. RR 范围合理；
8. 输出字段完整；
9. GUI 能显示 ECG 波形与 R 峰。

## 12. 风险清单

1. 字段名空格风险：已通过 `strip()` 策略降低风险。
2. 无参考标注风险：当前只能做 smoke test 和合理性验证，不能证明 R 峰检测准确性。
3. 50Hz R 峰检测精度风险：时间分辨率约 20ms，适合工程验证，但不等同于高精度 ECG 标注。
4. GUI 与算法同步开发风险：需避免 M1/M2 范围膨胀。
5. 医疗用途边界风险：本项目不得扩展为医疗诊断工具，除非重新决策。
